## Run it locally

1. Install **Node.js LTS** and **PostgreSQL 13 or newer** (or create a free Supabase project and use its connection string).
2. Create an empty database:
   ```bash
   createdb aidflow          # or create "aidflow" in pgAdmin
   ```
3. Set up the backend:
   ```bash
   cd backend
   cp .env.example .env      # then edit DATABASE_URL (your own password) and JWT_SECRET
   npm install
   npm run db:reset          # creates all tables + demo data
   npm run dev               # http://localhost:4000
   ```
4. Check it: open http://localhost:4000/health (should show `"database":"up"`) and http://localhost:4000/hospitals.
5. Run the frontend against it: in the project root create `.env` with
   ```
   VITE_API_MODE=real
   VITE_API_URL=http://localhost:4000
   ```
   then `npm run dev` in the root folder.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Start the API with auto-restart |
| `npm run typecheck` | TypeScript check, no output files |
| `npm run build` / `npm start` | Compile to `dist/` and run |
| `npm run db:migrate` | Apply new SQL files from `migrations/` (each runs once) |
| `npm run db:seed` | Add demo data (skipped if users already exist) |
| `npm run db:reset` | **Deletes everything**, rebuilds schema, seeds demo data (refuses in production) |

## Folder guide

```
backend/
  migrations/        numbered .sql files (001_init.sql = full schema)
  src/config/        env loading and validation
  src/db/            pool + withTransaction helper, migrate / seed / reset
  src/middleware/    error handler (one error JSON shape for every failure)
  src/modules/       one folder per feature (health, hospitals, later: auth, emergencies, dispatch)
  src/types/         contract.ts = copy of the frontend's src/types/contract.ts
  docs/              API_CONTRACT.md (share this with the team)
```

## Rules the schema already enforces

- Case IDs are generated by the database (`EMG-2026-0001`) and are unique.
- An ambulance can hold only one active case (partial unique index).
- Only one dispatch attempt per case can be `accepted`, and only one can be `pending` at a time.
- Latitude/longitude, statuses, roles and severities are validated by CHECK constraints.

## Notes

- Routes are at the root (`/hospitals`, not `/api/hospitals`) because the frontend client calls them that way.
